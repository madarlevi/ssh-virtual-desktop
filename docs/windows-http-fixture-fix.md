# Windows Rust HTTP fixture fix — 26 October 2026

## Root cause

The authenticated-download test's std TCP listener was set to nonblocking mode. On Windows the accepted socket inherits that mode. The background thread then called blocking-style read().unwrap() without waiting for readability. A client TCP connection can be accepted before curl has sent any HTTP bytes, so Winsock returned WSAEWOULDBLOCK (10035). Setting a read timeout does not switch the socket to blocking mode.

The panic closed the fixture connection, leaving curl without a complete HTTP response. The worker correctly reported Failed; the test's later Completed assertion was a secondary failure. No production download-engine change was necessary. The unmodified integration test passed once locally, consistent with an intermittent race. The new deterministic socket regression reproduces actual raw Windows error 10035 before allowing client bytes to be sent, then verifies successful request parsing through readiness waiting.

Primary references: [Windows accept socket properties](https://learn.microsoft.com/en-us/windows/win32/api/winsock2/nf-winsock2-accept), [Rust TcpStream blocking modes and timeout behavior](https://doc.rust-lang.org/std/net/struct.TcpStream.html).

## Exact changes

- Added test-only download_test_http.rs, using the existing Tokio dependency. Nonblocking sockets wait for readable/writable readiness; WouldBlock and Interrupted retry within fixed deadlines. Response writes advance by the actual byte count.
- Accept is bounded to 15 seconds per expected request, matching each worker's existing 15-second bound. Read/write processing retains a three-second bound, now covering the complete request/response rather than resetting indefinitely after each partial read. No server readiness sleeps were added.
- Request parsing accumulates split headers and complete Content-Length bodies, enforces the existing 64 KiB limit, and rejects malformed/duplicate lengths, oversized bodies, unsupported chunk framing and premature EOF.
- Startup uses a readiness channel. Each request returns its Result to the parent before the worker status assertion. The fixture thread contains no fallible network unwraps; a cancellation channel and joined thread handle early test exits.
- Authenticated GET and POST must still complete with exact payloads. Cookie, Authorization, Accept-Encoding, POST method/body, redirect rejection, no cross-origin connection and temporary credential cleanup assertions are preserved. The sink now accepts only WouldBlock as evidence of an empty backlog; unrelated accept errors fail the test.
- Reused the fixture in the cancellation and public-download tests, which had the same nonblocking accepted-socket hazard. Cancellation now sends real partial response bytes and holds the connection until the downloader closes it, replacing the server's timing-based chunk sleeps. Existing process/file condition polling remains bounded and is not used as a socket readiness fix.
- Missing real shell prerequisites now fail these worker tests instead of silently returning success. The helper module is cfg(test); application runtime behavior and dependency versions are unchanged.

Files: src-tauri/src/download_tests.rs, src-tauri/src/downloads.rs, new src-tauri/src/download_test_http.rs, CHANGELOG.md, and this report.
