# FreeBSD and Linux compatibility

FreeBSD is the primary remote compatibility target; Windows 10/11 x64 remains the only packaged client. Linux support is preserved. No reachable FreeBSD/Linux SSH test account was available during Update 3 development. Native CI and the connected checklist below are required before claiming end-to-end acceptance.

## Original failure and correction

The old setup ran `chmod 700 -- PATH`. FreeBSD's chmod treated `--` after the mode as a filename and reported `chmod: --: No such file or directory`. Download state directories now use SFTP mkdir/setstat with mode 0700; request files are created with mode 0600. The worker runs via `/bin/sh` and does not need chmod or an executable script bit. It sets umask 077 for files created by child tools.

The audit also removed GNU-only mv -T/editor replacement, ln -T publication and GNU-only copy options from FreeBSD paths. Copy adapters retain appropriate native behavior. Metadata/home resolution uses SFTP, not ls/stat/readlink parsing. Control commands explicitly enter /bin/sh; Bash is optional terminal integration only.

## Native CI coverage (configured, not yet executed)

`.github/workflows/ci.yml` first runs Windows Rust tests and exports workers generated by the actual Rust function. Dependent jobs run `tests/remote-worker.sh` on Ubuntu and a pinned FreeBSD 14.3 VM. The FreeBSD job installs no GNU packages and exercises base fetch, daemon, link and other base utilities. The Linux job tests available curl/wget/aria2c backends. The harness verifies actual HTTP payloads, filenames with leading hyphens/Unicode/quotes/metacharacters, file modes, collisions, cleanup, detached progress and marker cancellation. It does not establish an SSH/SFTP client session or launch Windows WebViews.

For a manual native run, export fixtures on Windows:

```powershell
cargo test --locked --manifest-path src-tauri/Cargo.toml export_workers_for_native_freebsd_and_linux_ci
```

Copy `src-tauri/target/compatibility-fixtures/` plus `tests/remote-worker.sh` to a disposable test workspace on each server, then:

```sh
/bin/sh tests/remote-worker.sh compatibility-fixtures
```

The harness requires native OpenBSD-compatible nc with -N (FreeBSD base nc and Ubuntu's netcat-openbsd), plus FreeBSD's sockstat or Linux's ss for listener readiness. Copy the entire generated fixture directory, including request templates and fetch-command.sh. It starts loopback-only synthetic HTTP endpoints and removes only a checked mktemp test directory. It does not install packages. These are development test dependencies, not application server requirements.

Failures report the backend, test phase, worker/backend exit codes, sanitized error classification, expected paths and actual file metadata. Request files and raw downloader output are never printed. Progress assertions wait for real bytes while the worker remains Downloading; they do not assume fetch's native buffers flush within a fixed delay. If a detached worker does not acknowledge cancellation, the private test directory is retained rather than removed underneath it.

Native FreeBSD 14.4 and Linux compatibility results, the original failure reproductions, and Windows build results are recorded in [the remote-worker verification report](remote-worker-verification.md). The GitHub Actions VM remains pinned to FreeBSD 14.3; that exact version was not available for the local verification.

## Connected Windows acceptance checklist

Run with a fresh and an existing profile on FreeBSD first, then Linux. Use disposable files and synthetic test sessions.

1. Connect with key/password after verifying the fingerprint; confirm the desktop shows FreeBSD/Linux correctly. Verify changed-key refusal separately.
2. Open Terminal, run uname -s, pwd and an interactive editor. Test multiple terminals and resize. Non-Bash shells retain their native prompt colors.
3. Browse /root where permitted, /home, /usr/home, /tmp, /var/tmp and the actual home. Enter a directory symlink; verify denied directories give errors. Create/rename/copy/move an isolated Unicode folder. Test scan depth, auto-update and Reload.
4. Edit a UTF-8 file, save it, check permissions and trigger a remote-edit conflict. Verify OpenSSH atomic rename extension support.
5. With only fetch on FreeBSD, choose a public HTTP/HTTPS URL without query parameters. Confirm backend fetch and no chmod error. Install optional tools yourself only if desired; repeat curl/wget/aria2c cases.
6. Open two native browser tabs and a second browser window. Confirm login sessions and loaded pages survive switching; titles/favicons/loading/navigation work. Test all README shortcuts with page focus and with address-bar focus; test terminal shortcuts independently.
7. Trigger extensionless Content-Disposition, redirect, download-attribute, JS and popup HTTP downloads. Confirm no Windows Save As or Downloads file appears. Confirm the remote picker appears every time.
8. Choose /root/downloads or another permitted directory; confirm and verify its file on the server. Compare a known hash where available. Cancel another picker and verify history stays unchanged.
9. Restart Windows client and reconnect the same saved profile: picker starts in the last confirmed path. Delete/make it inaccessible and verify fallback. Connect a second profile and verify independent history.
10. Observe actual bytes/speed with a slow fixture; cancel mid-transfer and verify partial/request cleanup and other jobs unaffected. Disconnect/reconnect during another detached transfer; completion must follow the recorded exit status.
11. Use synthetic cookie/authorization/POST endpoints. Confirm unchecked consent sends no session data; approve only to a trusted server. Confirm authenticated redirects fail without contacting the other origin. Missing bodies must fail visibly.
12. Trigger a blob/data download; decline its Windows-transfer checkbox, then retry with explicit approval. Verify its phase/status/size, final SFTP file, cancellation and temporary cache cleanup. Do not confuse this with a direct server download.
13. Confirm modals, Downloads, other workspace windows, taskbar and launcher stay above/clear of native browser content. Test high-DPI, monitor moves, maximize/minimize and closing tabs during load/popups.
14. Test NSIS/MSI installation, missing-WebView2 bootstrap, launch and uninstallation in a clean Windows VM. Local installer generation alone does not verify this.

## Remaining limits

Resume across separate jobs and automatic authenticated redirect continuation are deliberately unsupported. Fetch cannot protect query URLs in process arguments and cannot replay advanced requests; use curl, aria2c or wget for eligible URLs. Detached jobs do not survive reboot, forced termination or restrictive server logout policies. Hard-link publication needs a supporting filesystem. Client-mediated transfers need the client/tab/SSH connection and are not persistent. Universal website compatibility, native browser interception ordering, SFTP extension behavior and live FreeBSD/Linux workflows remain unverified until the above tests run.
